# Clarity CDSS — Clinical documentation workspace

A standalone, static worksheet based on the Clarity CDSS v3 blueprint and inspired by its public reference site. Open `index.html` in a modern browser. There is no build step, backend, authentication, package installation, or diagnostic-engine integration.

## Implemented

- Professional light and dark themes with an accessible header toggle, operating-system preference as the initial default, and a saved browser-local preference shared by the workspace and reference library.
- De-identified intake, observations, SOCRATES, history, examination, comorbidities, clinician-checked red flags, optional bedside/lab values, and ECG notes. BMI is calculated live from valid entered weight and height. For adults 18+, the workspace shows WHO adult screening categories only when pregnancy is not recorded as present or possible; child/adolescent and pregnancy cases receive an explicit limitation instead. Categories are not diagnoses, and the WHO reference is linked.
- Local calculations for NEWS2, qSOFA, SIRS, GCS, CURB-65, Shock Index, and MAP, with incomplete-input handling and numeric range validation. Out-of-range or wrong-precision numeric values are excluded from calculations and identified in generated worksheets. These calculations are unvalidated and must not be used to guide patient care.
- Pediatric mode requires age context and pediatric weight to prepare a worksheet, and suppresses NEWS2, qSOFA, SIRS, and CURB-65 because pediatric use is not validated here. Obstetric mode notes that scores are not pregnancy-adjusted. Other displayed calculations are also unvalidated.
- A specialty registry with an acute core and 22 optional module documentation scaffolds, dynamically rendered structured fields, module-specific checklist flags, and live per-module field-entry counts. Counts describe whether fields have a value; they are not clinical completeness or quality assessments.
- Searchable structured symptom/finding labels. These remain unselected until the clinician explicitly confirms them; they are documentation labels and do not drive automated inference.
- A diagnosis workspace with switchable **Documentation only** and **AI / demo** modes. Documentation mode preserves clinician-authored records only. The AI/demo mode offers seven unranked teaching candidates for a fixed prewritten sore-throat vignette and links to topic references to preview the review UI; it is explicitly not AI-generated, does not read or transmit patient fields, and is not for clinical use. Demo certainty is not generated; approximate illustrative WHO ICD-10 mappings are displayed but are not verified or patient-specific and must be checked in the official WHO browser. No management advice is provided; linked sources are not automatically applied to patient care. Real AI generation remains unavailable until an approved AI service is configured.
- Optional clinician-authored documentation for up to seven diagnoses, manual ICD-10 code entry, clinician-set status/rationale, and a clinician-written management/follow-up note with source/version citation. None of these fields is generated, coded, checked, or clinically validated by the app; codes and guidance must be independently verified.
- A fail-closed diagnostic-engine integration scaffold. The page checks a same-origin readiness endpoint only after a clinician selects AI/demo mode, without sending case data. Real generation remains disabled unless an authenticated clinician session, configured AI engine, clinical approval, scope, and CSRF token are reported; explicit per-request consent is also required. This folder contains no backend or AI engine. See [DIAGNOSTIC-INTEGRATION.md](DIAGNOSTIC-INTEGRATION.md) before implementing a service.
- Printable/Word-compatible worksheet reports, an in-memory audit timeline with chronological event playback/order controls, and JSON/CSV audit export. Reports identify clinician-authored diagnoses, ICD-10 codes, management notes, and citations as unverified, and label score results as unvalidated calculations. Replay shows event names and timestamps only; it does not recreate patient data or assessment state.
- A searchable module, calculation, and symptom/finding registry. Each of the 23 specialty modules has its own link to a relevant professional-society or guideline source, in addition to global and East African agency portals. Links are external clinician references only; the app does not fetch or use them to generate diagnoses, rationales, or recommendations. Clinicians must verify current status, jurisdiction, scope, and applicability.

## Safety and limitations

This is **not a diagnostic system, medical device, or validated clinical product**. The seven canned demo candidates are not AI, are not ranked or derived from patient information, and are not clinical advice. The demo does not assign certainty percentages or produce management plans. It shows approximate illustrative ICD-10 mappings for interface demonstration only; these are not verified, not patient-specific, and must be confirmed in the official WHO classification. Candidate-linked sources are examples for independent review, not patient-specific guidance. This deployment has no AI engine, clinical evidence retrieval, or approved specialty algorithms. Real draft generation requires a separately implemented same-origin backend and documented clinical approval. A future service's output would still be unverified decision support, not a diagnosis or treatment instruction; per-item review controls record only a transient clinician review decision. The app does not independently verify diagnosis labels, certainty estimates, codes, evidence, guidelines, or management considerations. Score calculations and specialty modules are unvalidated and must not guide patient care. Clinicians must independently assess the patient and verify any diagnostic documentation and management plan using current approved sources.

This folder includes no diagnostic backend, authentication provider, AI engine, durable archive, or server-side audit. The page makes no network request until AI/demo mode is selected; its readiness request sends no case data. Real case data is sent only after a successful readiness check, explicit consent, and a clinician's AI generation request. The synthetic demo never reads case data. Do not enter identifying patient information. The audit is held in page memory. External sources are opened only when clicked. Report downloads include entered worksheet values; selected image file contents and filenames are excluded.

## Files

- `index.html`, `styles.css`, `app.js`, `theme.js`: assessment interface, themes, calculations, workflow, and reports.
- `clinical-registry.js`: specialty, taxonomy, and score metadata.
- `guidelines.html`, `registry-page.js`: searchable reference and coverage/status library.
- `DIAGNOSTIC-INTEGRATION.md`: required server-side security, approval, request, and response contract for a future integration.

## Verification

There is no package manifest or test runner. Open both HTML pages directly in a modern browser and verify the form, registry filtering, calculations, report export, and audit functions. Verify that documentation-only is the default, the synthetic demo is clearly labeled and independent of the patient form, and real AI generation stays unavailable without a configured service. Specialty module progress is documentation-only; fields and red-flag checklists do not activate diagnostic, triage, or treatment algorithms.
